# 墨修

**两界穿越修仙经营挂机游戏** — 表世界修仙界 · 里世界现代都市 · 每日界潮双向跨界倒卖。

极简黑白文字风，响应式网页（PC 三栏 / 移动单列），原生 ES Module，**无构建**。单机零依赖；邮箱账号按需加载随源码附带的 Supabase SDK 2.117.2。

---

## 当前版本

首页与界门保留快捷入口，主要导航收束为修炼、探索、经营、势力、更多。支持两界委托、客户关系、故事分支、玩家交易与竞技、聊天称号和每日签到。新增四种互斥套路、四种机制词条、金丹穿越者主线、持续世界状态；详情见 [S级体验深化](DEPTH_UPDATE.md) 与 [六阶段基础优化](EXPERIENCE_UPDATE.md)。

## 玩法

玩家原本生活在现代世界，意外获得连接两个世界的「界门」能力。

- **表世界（修仙界）**：修炼、战斗、功法、法宝、宗门、灵兽、灵田、炼丹、飞升
- **里世界（现代都市）**：科技、资金、商业、研究、地产、休闲生活

两界的**货币互不相通**——灵石只能在修仙界花，人民币只能在现代花。
所以你必须双向带货，才能同时供养两条线。这正是《墨修》区别于普通挂机修仙的地方。

核心循环：**发现机会 → 跨界倒卖 → 获得资本 → 投资生产 → 强化修仙 → 解锁新资源 → 反哺另一世界**

## 运行

项目使用原生 ES Module，**不能用 `file://` 直接打开**（浏览器会拦截模块脚本）。起一个静态服务器即可：

```bash
cd moxiu
python3 -m http.server 8080
# 打开 http://localhost:8080
```

- 「更多 → 碎片商店」支持微信赞赏申请、人工核对充值、永久称号与有限休闲扩容。¥1=10 天道碎片，支持 1/5/10/25/50/100 元；余额和权益独立保存，清档、轮回保留。审核管理员 UID 10000001；操作与价格见 [赞赏充值与碎片商店](docs/赞赏充值与碎片商店.md)。

- 邮箱角色由共享服务器引擎结算货币、离线收益、NPC贸易、生产、战斗与剧情，操作有版本校验和幂等回执。真实玩家交易与竞技已提供独立服务器结算；本地试玩不参与共享资产和排行。

## 时间模式

| 模式 | 世界时钟 | 倍率 | 界潮 |
|---|---|---|---|
| **标准**（默认） | 每帧对齐真实时间 | 固定 1× | 每日 05:00 全服统一刷新 |
| **沙盒** | 按倍率推进 | 1× / 10× / 60× | 与全服脱钩 |

标准模式是为将来的联机档准备的——只有时钟对齐真实时间，「界潮是全服统一的跨界窗口」才成立。
标准1倍速的自动化策略对照首轮约9–13.3天；想加速体验可以切到沙盒。

## 目录结构

```
index.html              入口
assets/css/             黑白视觉规范、三栏/单列响应式
src/core/               状态 / 存档 / 存档后端 / 时间模式 / 时钟 / 主循环 / 事件总线
src/data/               境界、道途、商品、功法、装备、副本、宗门、道盟、奇闻……
src/systems/            修炼、界潮、市场、交易行、副本、灵田、炼丹、灵科、道盟、宗门……
src/ui/                 顶部栏、视图、浮层
docs/                   开发计划、GDD 原文、数据库迁移脚本
```

**分层规则**：`data` 是无副作用纯数据 → `systems` 只操作 state 并抛事件 → `ui` 只读 state、只调 systems。

## 开发

没有构建步骤，改完刷新即可。架构上有一条硬约束值得注意：

**`character.js` 只读原始数据，不调用任何 systems 模块。**
因为 `guild` / `ranking` / `tradehouse` / `sect` 都要反向依赖它来取属性，
一旦它反过来调用它们就会成环。需要新的加成来源时，直接读 `state` 或 `data/*` 即可。

## 设计红线

- 核心身份不可动摇：两界套利 → 灵科融合 → 修仙反哺现代
- 系统联动：任何系统都必须与至少两个其他系统产生联系
- Idle 定位：在线收益不能碾压挂机收益，深度玩家收益只比轻度玩家高 30-50%
- 科技平衡：现代科技中期走向融合，后期修仙反超
- **Pay-to-Win 禁止**：付费不能成为最优 Build 的一部分
