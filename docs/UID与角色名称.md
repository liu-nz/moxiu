# UID 与角色名称

每个 Supabase 游戏账号对应一个 `public.moxiu_player_profiles` 档案。内部仍通过 Auth UUID 做授权；玩家看到的是从 10000001 起由数据库 identity 序列分配的 UID。UID 唯一，不承诺连续，不属于密码或付款证明。

新注册须填写 2–16 位中文（基本汉字）、英文字母、数字或下划线的角色名称，自动去除前后空格。名称可重复，UID 区分账号。前端提交 `options.data.role_name`；数据库 Auth 创建触发器再次校验，缺名或非法名字会回滚新账号创建，不能绕过页面直接注册无名角色。

已有账号保留游戏进度，补发 UID。未提供有效名字的旧账号默认显示「初来行者」，可在设置 → 云端账号中补设一次角色名称。新账号选定名称后暂不支持改名。

行者档案、人物页和云端账号浮层展示身份及复制 UID 按钮；手机可在人物页或设置中查看。本地试玩没有账号 UID。档案从服务端读取，不使用可编辑的存档或 Auth metadata 作为身份来源。读取失败停止启动并提示重新载入，不生成替代 UID。

Auth 用户创建、UID 与档案创建在同一数据库事务内。档案启用 RLS，登录者只能读自己的记录，客户端没有 INSERT/UPDATE/DELETE 或序列权限。旧账号初次命名 RPC 只允许操作本人的未确认名称，不接受 UID 参数；确认后不能再调用改名。权限提升仅在不对 REST 暴露的私有 schema 内，使用固定空 search_path 和 auth.uid() 约束。

轮回、导入或重置角色进度不影响档案。删除整个 Auth 账号会级联删除其档案；重新注册是新账号，会获得新 UID。Auth metadata 中的后续改名也不会改变已确认档案。

验证：`tests/player-profile.cjs` 覆盖名称规则、真实 SDK 注册参数、缺名拦截、访客提示、服务器身份展示、复制、旧账号补名、轮回与重置保留、档案读取失败和手机布局；`tests/cloud.cjs` 回归云同步。`tests/player-profiles.sql` 在真实数据库中测试 UID 生成、重复名字、非法注册、RLS、不可直接修改身份、补名一次、存档隔离；事务回滚测试账号和存档（序列号可能留下正常间隙）。

当前仍受邮件发件服务与认证回跳地址配置的既有约束。真实邮箱发送与验证由玩家本人操作，测试不会发送邮件。
