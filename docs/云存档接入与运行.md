# 邮箱账号与云存档封测

已复用 LiuNian 组织的现有免费项目 `zqgcijakvjzvvtecdacj`，地域 `ap-southeast-1`。未新增付费资源或发布网页。

启动：在仓库根目录执行 `python3 -m http.server 3000`，访问 `http://localhost:3000/`。原有 8080 入口也可试玩，但邮件验证/找回密码建议统一从 3000 入口操作。

## 操作

1. 可直接本地试玩，现有系统保留。
2. 在设置中打开邮箱登录。使用 Supabase 控制台账号的邮箱注册游戏，设置至少 8 位游戏密码，查收验证邮件。
3. 邮箱验证后恢复登录，进入账号自己的角色；本地试玩不自动导入。
4. 人物存档页可立即保存、导出、导入或重置。云端导入和重置等待远程确认后才重载；未保存成功时保留当前游戏供导出。
5. 同账号双设备同时保存，过期版本停止写入，重新载入后选择云档或本机备份继续。断网/结果不确定时也先重新读取，避免盲目覆盖。

## 数据与权限

`public.moxiu_test_saves` 以 `auth.users.id` 的 UUID 为主键，保存 JSON 快照、递增版本和服务端更新时间。匿名角色没有访问权；登录角色的读写都受本人 UID 的 RLS 约束。

`moxiu_write_test_save` 使用 security invoker，固定空 search_path，并仅向 authenticated 授予执行权限。期望版本为 0 时只创建；更新只允许当前版本匹配的记录，返回空结果即冲突。JSON 必须含 player/currency 对象且不大于 1 MiB。

前端仅使用 Publishable key。SDK 固定 2.117.2，从 npm 正式包取出 UMD 文件，下载完整性校验与 MIT 许可随 `assets/vendor/` 保存，页面不依赖海外 CDN。

本机备份以用户 UID 分开。启动读取失败会停在可重试页面。导入、重置、退出账号时暂停自动及关闭页面保存，防止重载前旧角色回写。

迁移已通过 Supabase 执行，SQL 位于 `supabase/migrations/`。旧 `online-迁移脚本.md` 适用于历史平台，其 TEXT 用户 ID 与匿名授权方案不适用于此项目。

## 验证

- `node tests/single-player.mjs`：原有单机逻辑。
- `node tests/single-player-ui.cjs`：原有 26 个视图和移动端回归。
- `node tests/cloud.cjs`：SDK 登录错误、账号隔离、保存串行、备份恢复、冲突、重置及读取失败。浏览器用隔离上下文和模拟网络，不使用用户凭据或发送实际邮件。
- 真实 PostgreSQL 内以事务测试存档创建/更新、旧版本拒绝、异常 JSON 拒绝和跨账号读写拒绝，最后回滚所有测试用户和存档。
- 真实匿名 REST 访问返回 401，Supabase 安全检查无告警。

真实邮箱验证仍需本人操作。默认 SMTP 仅支持项目成员邮箱且每小时 2 封；网站公开注册前必须配置发件服务。认证返回地址在 Supabase Authentication → URL Configuration 管理；若改过默认 Site URL，应将其设为本地测试入口并加入对应 Redirect URLs。

## 后续联机范围

目前只有账号和个人云同步，未提供真实玩家交易、玩家排行榜、聊天或宗门联机。此表允许客户端写自己的测试快照，不具备多人公平经济的可信度；正式多人余额、物品、离线奖励及交易须先由服务端结算并独立存储。当前 NPC 榜单/交易继续作为单机内容。
