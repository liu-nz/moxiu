登录后直接进入原有首页。首页、市场、界门、人物和所有玩法共用一份角色、货币、背包与境界；移除「联机试运行」菜单和独立钱包页面。

## 结算方式

- 原有 92 项玩家操作通过 moxiu-game Edge Function 执行，包括交易、穿越、仓库、职业经营、种田养殖、制作研究、装备功法、副本、宗门、道侣、工程、委托、目标、奇闻及轮回。
- 服务器运行同一份现有游戏规则，使用可信角色、服务器时间和数据库中的付费扩容权益；客户端不提交价格、奖励、时间、随机数、跳过消耗或角色存档。
- 收入、修炼、生产、自动化及离线收益随服务器时间推进。保留原有三天离线结算上限；登录角色固定标准 1×，页面可见时每 15 秒同步，操作前也结算经过的时间。
- 私有角色表和请求表不授予匿名或普通登录用户直接读写权限。Edge Function 使用 getUser 核验令牌，再以服务端内置 service_role 调用私有结算接口。服务密钥不会进入网页。
- 每账号事务锁、版本检查及请求编号保证原子提交。另一设备已更新时返回最新角色并拒绝旧操作；响应丢失时保留原编号，暂停后续操作，允许重新载入后重试，不重复扣款或发奖。
- 充值钱包继续使用原有独立充值账本。游戏清档不会删 UID、付款记录、称号或扩容权益。
- 旧单机云测试存档与实验钱包不导入新角色。旧实验 RPC 已撤销登录用户执行权限。

## 修改游戏规则后的发布

网页与 Edge Function 使用相同版本的规则。修改 src/systems、src/data、结算引擎或指令白名单后，需要一起重新打包并发布服务器函数，不能只更新网页。

打包工具使用 esbuild 0.25.12，运行：

```sh
ESBUILD=/path/to/esbuild node scripts/package-game-function.cjs /tmp/moxiu-game-files.json
```

该 JSON 包含 index.ts 与自包含规则模块，交给 Supabase Edge Function 部署工具。平台 verify_jwt=false 时必须保留处理器中的 getUser 验证；无有效玩家身份的请求返回 401。部署的服务密钥仅取自平台内置环境变量。
