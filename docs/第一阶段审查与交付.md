# 《墨修》第一阶段审查与交付

本阶段基于 main 提交 `43ed2709e28ff0175b8269a0b4eafa78310fc0ef`，限于首页、导航、界门确认与两界视觉，以及直接影响这些流程的旧问题。保留全部已有系统。未重写市场公式、收益曲线、副本机制或轮回规则。

## 源码结构与现状

仓库包含 82 个 JavaScript 模块，约 12,532 行源码（实施后统计），原生 ES Module、无构建步骤。已检查入口、全部模块依赖与语法，重点跟踪启动/存档/时钟/主循环、人物属性、成长、背包、界潮、市场与交易、洞府与自动化，以及其页面入口。

| 层 | 责任与审查结论 |
| --- | --- |
| core | 状态、事件、时钟、循环、本地存档及可注册后端；目前默认只有本地存档，云端接口是预留能力 |
| data | 境界、装备、功法、商品、作物、灵兽、研究、道侣、副本、宗门、道盟、地产、事件与轮回定义 |
| systems | 操作状态并发事件；人物模块直接读取数据，避免反向导入各玩法形成依赖环 |
| ui | 顶部、三栏、16 个原有视图文件及通用浮层；新增首页和界门视图 |
| docs | GDD、开发计划及未来云端迁移说明；部分文字滞后于实现 |

原页面已在真实 Chrome 中启动、查看并截图。原三栏在 1440px 下基本可读，但现代开局中栏直接显示长职业列表，修炼目标和穿越玩法不突出；顶部世界按钮立即穿越、立即扣次数；移动底栏有十多个入口；右栏背包与左栏界门重复展示。无明显实施阻塞。

道盟、交易行和排行榜当前包含 NPC 模拟逻辑，不能视为已接通真实多人服务。README 提到的“237 项断言”验证脚本未随当前仓库提交，本轮另附可复跑的浏览器验证脚本。

## 第一阶段修改

1. 混合首页：中间展示境界、实时修为、修炼速率、下一晋层/突破目标、剩余修为及世界时间下的预计时间；左侧展示人物和成长入口；右侧展示界潮、当前世界行情及近期记事。
2. 回流与休闲：本次启动离线报告展示在首页，灵田/牧场待收数量实时更新，可直接收获；管理入口保留洞府、养殖和战斗灵兽。现代事业、地产、生活均可继续访问。
3. 导航：统一首页、修行、界门、经营、更多五入口；修行/经营有二级分类，更多列出本世界全部系统。请求另一世界的本地玩法时引导至界门，不自动穿越。现代世界仍可查看半速修炼。
4. 界门：完整背包清单、载重、目的地当日需求榜、当前可售贸易商品估价、次数与刷新说明；确认后约 1.6 秒过渡、抵达反馈和当地市场入口。空包可以穿越，超重/次数耗尽不能穿越。过渡中背包或行情日变化需要重新确认，重复调用不能重复扣次数。
5. 两界视觉：修仙界纸墨色、宋体、古籍感；现代世界网格底、清晰面板、无衬线标题。移动优先展示中栏，固定五个底部入口。
6. 直接流程修复：首次择道免费，后续改修规则不变；提示兼容字符串与事件对象；强制浮层标记传递并添加键盘焦点循环；启动成功隐藏兜底提示；修正境界路标遗留 MVP 文案；穿越过渡期间延后奇闻弹窗。

## 验证

真实 Chrome 无头测试，桌面 1440×1000、手机 390×844：

- 26 个当前两界页面渲染检查；另在炼气顶层、筑基、金丹、化神、渡劫阶段共 130 次渲染检查。
- 首页、目标、五入口、更多系统、世界按钮仅进入确认页、不提前扣次数。
- 空包往返、约 1.6 秒过渡、抵达、超重、次数耗尽、重复调用、过渡期间背包变化不扣次数。
- 首次免费择道及下一引导跳转、字符串提示、强制浮层背景点击不关闭、启动兜底隐藏。
- 手机主要页面没有横向溢出；82 个源码模块语法通过，未发现缺失本地 import；diff 空白检查通过。

这些是基本自测与渲染验证，不代表完整经济平衡、长周目、云存档或真实联机已验证。

### 复跑

启动本地静态服务器：`python3 -m http.server 8080 --bind 127.0.0.1`。

使用已安装的 Playwright 运行 `node tests/phase-one.cjs` 和 `node tests/phase-one-edges.cjs`。可通过 `PLAYWRIGHT_MODULE` 指向已有 Playwright 模块，`CHROME_PATH` 指向 Chrome 可执行文件，`MOXIU_URL` 指向预览地址。使用独立临时浏览器上下文，不影响玩家日常浏览器存档。截图写入忽略的 `test-results/`。
