# 《墨修》第二阶段：市场、经营与时间结算

日期：2026-10-02。基于第一阶段的 `codex/phase-one-ui`，第二阶段分支为 `codex/phase-two-economy`。

## 这次改变了什么

| 部分 | 原有问题 | 完成后的行为 |
| --- | --- | --- |
| 市场 | 买卖和丹药挤在同一长页，难以判断带什么货 | 分为进货、出货、丹药；展示目的地需求、当前回款与剩余载重，价格公式默认折叠 |
| 批量价格 | 首件价格乘整批数量，忽略批内供货涨价及饱和 | 买入和卖出都按每件累计数量定价；混合品质共享同商品销量 |
| 成交反馈 | 买卖直接执行，过期页面也可能继续成交 | 先确认整批报价；当行情或背包变化时更新报价，要求再次确认 |
| 可购数量 | 忽略背包已有货物，按首件价格计算预算 | 同时考虑剩余载重、整批成本与当地余额；实际交易层再次校验 |
| 本地回收 | 贸易加成可导致在同一世界买入后卖出刷钱 | 本地回收最多按未涨价进货基准八折，再计品质及饱和；进货页提示适合跨界出售 |
| 投资选择 | 工资、商业、地产只列总数和按钮 | 展示升级成本、新增收入与预计回本；停工时不虚报工资回本 |
| 店铺 | 现代店铺在修仙界也会卖现代货、收灵石 | 仅在现代界代售修仙货；渠道抽成 8%，按整批饱和价结算；离开后租金仍按原有半速规则继续 |
| 交易行 | 人民币定价的数值被直接当作灵石税费 | 按挂单的收款货币缴纳 2% 上架费，原商会减免仍生效；修复失效物品选择和非法输入 |
| 收支记录 | 成交后只有提示 | 记录最近 40 笔市场、店铺、交易行收支，页面显示当地货币的最近 6 笔 |
| 界门估价 | 单价乘总数，未计批内饱和 | 估计目的地可出售跨界货物的整批回款，沿用成交报价规则 |
| 后台恢复 | 标准模式离开两小时只补一分钟产出 | 与离线结算共用推进路径，最多结算三天真实时间 |
| 跨日刷新 | 长时间片生产完才刷新，日期与每日统计混杂 | 在每日 05:00（UTC+8）边界切片，先结算旧日，再刷新界潮、行情、统计和日常职责 |
| 居所加成 | 净人民币变化被整体加成，售货也可获得额外回款 | 仅加成离线修为及工资、商业、租金；加成修为后再次检查晋层与封顶 |

## 结算规则与取舍

- 两界货币继续独立。目的地机会按当前每公斤回款排序，没有引入人民币和灵石的统一汇率，也没有把跨币回款标成保证利润。
- 买入第 j 件时，供货系数采用已有进货量加 j；整批成本采用等差求和。
- 卖出第 j 件时，饱和度采用已有销量加 j，最低维持 35%。价格到达底线后的尾段直接求和，避免大数量造成长循环。
- 一个商品的不同品质共享销量；整包报价顺序与实际出货顺序一致。
- 购货不能超过当前界门载重。灵田和其他生产仍可积累超过载重的货物，玩家可以本地回收、挂交易行或先出售部分货物。
- 现代店铺保留自动化用途，代售便利会收渠道费；没有把库存清算收入包装成稳定新增收益，也没有承诺固定店铺回本时间。
- 离线与后台恢复均以三天真实时间为生产上限，沙盒按既有倍率推进世界时间。超过上限后，标准模式只同步当前日期和界潮，跳过的尾段不发生产收益、职责或月俸。
- 同一状态完成离线结算后更新保存时间，避免同一区间重复补发。临时状态到期也会切分时间片，不把已到期加成用于整段离线收益。
- 种田、养殖、灵兽、道侣、功法 Build、装备、副本、现代经营、跨界贸易、地产、轮回全部保留。第三阶段的副本与 Build 深层改动未展开。

## 使用与审阅

纯静态项目，无构建依赖。将源码放进一个文件夹，从该文件夹启动静态网页服务，再访问首页。例如使用 Python 本地服务：`python3 -m http.server 8080 --bind 127.0.0.1`。

本阶段不要求清档，新增收支记录与统计字段按需初始化。已有测试档会使用新的市场定价、店铺与上架费规则。源码包包含第一阶段和第二阶段的完整成果。

第一阶段 PR 仍未合并，因此第二阶段 PR 以第一阶段分支为基础。审阅和合并时先处理第一阶段，再把第二阶段的目标分支切换到 `main`；若第一阶段使用 squash/rebase 合并，第二阶段需要重新建立在合并后的 `main` 上，再复查差异。

尚未验证长期周目整体平衡、云存档冲突或真实联机经济。交易行继续采用 NPC 模拟，市场不是服务器权威经济；这次没有部署公开站点。
